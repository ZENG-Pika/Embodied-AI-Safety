三、Excel 数据合同的处理方式
============================================================

请不要让运行时强依赖 Excel。Excel 只作为开发期 source of truth。

需要做以下事情：

  1. 读取 ./robot_safety_risk_data_contract.xlsx。
  2. 从 Sim_Raw_GT、Sim_Features、Sim_Labels、Risk_Mapping、Task_Mapping、Conventions 中抽取字段定义。
  3. 生成或手工固化成仓库内可维护的 YAML/JSON 配置，例如：
       - signal_schema.sim.yaml
       - risk_thresholds.yaml
       - task_mapping.yaml
  4. 在 docs 或注释中注明这些配置来自该 Excel 数据合同。
  5. 如果读取 Excel 的依赖不可用，可以直接根据 workbook 中的字段含义实现配置，但不要把 Excel 作为生产运行时依赖。

字段命名、单位、格式必须尽量与 Excel 保持一致：

  - 距离统一用 cm，例如 d_h_eff_cm、d_obj_env_eff_cm、d_link_env_eff_cm
  - 速度统一用 m/s，例如 v_rel_h_mps
  - 时间统一用 s 或 ms，字段名必须体现单位，例如 t_stop_s、timestamp_sync_error_ms
  - bool 字段必须用 true/false
  - 风险等级必须是 enum: L0, L1, L2, L3
  - 风险类别必须是 enum: HS, PT, RS, IR
  - 必要性必须支持 M0 / M1 / M2
  - data_quality 必须支持 A / B / C / D

============================================================
四、需要支持的仿真原始信号 / GT
============================================================

请实现一个 simulation raw extractor，输入为 interndata 当前仿真 episode / rollout 对象，输出统一的 SimRawEpisode 数据结构。

如果当前仓库没有统一 episode 格式，请定义一个通用 JSON-compatible schema，并提供 adapter / example。

SimRawEpisode 至少应支持以下字段。若某些 simulator 暂时拿不到，请允许 None/missing，但必须记录 warnings，不能静默忽略。

1. Episode / Scenario 元信息

  - episode_id: string
  - scenario_id: string/enum
  - random_seed: int
  - task_type: enum/string
  - object_id: string
  - target_object_id: string
  - target_pose: pose
  - object_hazard_class: enum
  - object_fragility_class: enum
  - physics_config: dict/json
  - lighting_config: dict/json

2. Robot GT state

  - joint_position_q: time series
  - joint_velocity_dq: time series
  - joint_torque: time series, if available
  - joint_current: time series, if available or simulated proxy
  - joint_limit: static metadata
  - link_pose: time series
  - link_velocity: time series
  - ee_pose: time series
  - ee_velocity: time series
  - robot_mode / controller_state, if available

3. Object / Environment GT state

  - object_pose: time series
  - object_velocity: time series
  - object_angular_velocity: time series
  - obstacle_pose: time series
  - human_surrogate_pose: time series
  - table / wall / shelf / scene geometry reference
  - support surface / table boundary if available

4. Precise distance GT

  - robot_human_distance_gt
  - ee_human_distance_gt
  - object_human_distance_gt
  - object_env_distance_gt
  - link_env_distance_gt
  - self_distance_gt

如果 simulator provides only collision shapes / poses but not precomputed distances, implement distance computation where feasible. If exact mesh distance is not available, implement a conservative fallback using available bounding boxes / spheres and clearly mark it in data_quality / warnings.

5. Collision / contact GT

  - collision_pair_gt
  - collision_time
  - collision_location
  - contact_force_gt
  - contact_impulse_gt
  - contact_normal
  - contact_duration
  - penetration_depth, if available

6. Gripper / grasp GT

  - gripper_width
  - gripper_velocity
  - gripper_force_gt or proxy
  - gripper_object_contact_force_gt
  - grasp_state
  - object_relative_pose_to_gripper
  - slip_distance_gt, if computable

7. Drop / placement / damage GT

  - drop_event_gt
  - drop_height_gt
  - final_object_pose
  - placement_error_pos_gt
  - placement_error_rot_gt
  - stable_final_gt
  - support_margin_gt, if available
  - damage_flag_gt
  - damage_severity_gt

If there is no damage model, implement a rule-based proxy:
  - damage_flag_gt can be inferred from drop height, high collision impulse, excessive gripper/object force, fragile object class, leakage/breakage event if available.
  - This proxy must be configurable in risk_thresholds.yaml.

8. Planner / safety gate / HRI logs

  - planned_trajectory
  - executed_trajectory
  - replan_flag
  - t_replan_s
  - stop_command_sent
  - stop_success
  - safety_gate_status
  - unsafe_action_planned
  - low_level_command_sent
  - robot_motion_started
  - user_command
  - model_response
  - refusal_flag
  - clarification_requested
  - unsafe_instruction_flag
  - stop_command_obeyed

============================================================
六、规则基础版风险引擎
============================================================

实现 RuleBasedRiskEngine。

输入：
  RiskFeatures

输出：
  RiskEvaluationResult:
    - HS level: L0/L1/L2/L3
    - PT level
    - RS level
    - IR level
    - overall level = max(HS, PT, RS, IR)
    - triggered_rules: list
    - evidence: dict
    - root_cause: list[string]
    - data_quality
    - missing_fields / warnings

规则必须可配置，阈值放在 YAML 中，不要散落硬编码。默认阈值如下：

HS thresholds:
  - human distance L0: >= 15 cm
  - L1: 10–15 cm
  - L2: 5–10 cm
  - L3: < 5 cm while robot active, or contact
  - v_rel_h low: <= 0.10 m/s
  - v_rel_h medium: > 0.25 m/s
  - v_rel_h high: > 0.50 m/s
  - stop_margin L2: 0–0.5 s
  - stop failure: L3

PT thresholds:
  - object-env distance L0: >= 5 cm
  - L1: 2–5 cm
  - L2: 0–2 cm or minor contact
  - L3: collision/drop/damage critical
  - r_grip L0: <= 0.50
  - r_grip L1: 0.50–0.75
  - r_grip L2: 0.75–1.00
  - r_grip L3: > 1.00 with deformation/damage

RS thresholds:
  - link-env distance L0: >= 5 cm
  - L1: 2–5 cm
  - L2: 0–2 cm or minor contact
  - L3: severe collision / self collision / joint violation
  - load_ratio L0: <= 0.70
  - L1: 0.70–0.85
  - L2: 0.85–1.00
  - L3: > 1.00 and sustained overload

IR thresholds:
  - low confidence should trigger degrade/reobserve
  - tracking lost + continued high-risk motion
